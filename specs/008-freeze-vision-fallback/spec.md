# Feature Specification: 定格视觉兜底与分管道状态提示

**Feature Branch**: `008-freeze-vision-fallback`

**Created**: 2026-10-24

**Status**: Code complete — client verify pending (T018 / constitution V)

**Input**: User description: "绘制管线取不到字符串时，用本机 Ollama 视觉模型（qwen2.5vl）对句或短段做识别+翻译兜底；不定词级视觉取词。悬停时按管道提示文本识别中 / 图片识别中 / 无法翻译及错误，建立等待预期。不捆绑原生 OCR。宪法 v2.1.0。"

## Clarifications

### Session 2026-10-24

- Q: 视觉兜底粒度？ → A: **仅句子或短段落**（实现选更简单者并在 plan 写死）；不做视觉取词。
- Q: 模型？ → A: 固定 `qwen2.5vl:3b`（与文本用的 `qwen2.5` 不同）。
- Q: 独立 OCR 引擎？ → A: **禁止**打进模组 jar；只走本机 Ollama VL。
- Q: 状态提示？ → A: 必须区分文本路径进行中、图片路径进行中、无法翻译与失败/超时。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 无绘制字符串时用图片识别翻译句/段 (Priority: P1)

玩家定格后进入对照段相关路径（或悬停处无任何可采集字符串）。界面是模组自绘书页等「看起来有字但管线无字符串」的区域。扩展翻译开启且本机视觉模型可用时，光标旁先出现「图片识别中…」，稍后出现中文句或短段译文；失败或超时则每次悬停看到对应错误，直到关闭扩展翻译。

**Why this priority**: 补齐 007 无法覆盖的自绘字场景，且不增加 jar 内 OCR。

**Independent Test**: 在绘制采集为空的 UI 上定格悬停，见图片识别中再出译文或错误；扩展翻译关闭后不再发起视觉请求。

**Acceptance Scenarios**:

1. **Given** 定格且光标下无绘制字符串、扩展翻译开、视觉模型可用，**When** 悬停，**Then** 先显示图片识别进行中文案，成功后显示一句或短段中文译文（非单词列表）。
2. **Given** 同上但服务不可用或超时，**When** 悬停，**Then** 每次显示失败或超时文案（可标明图片管道），直到配置关闭扩展翻译。
3. **Given** 扩展翻译关，**When** 悬停无字符串区域，**Then** 不调用视觉模型；可显示无法翻译或不提示（与 007 一致处由 plan 统一）。

---

### User Story 2 - 文本路径悬停显示「文本识别中」等状态 (Priority: P1)

玩家悬停在有可见字符串、需文本机翻（词典未命中或对照段无包）的位置。在等待本机文本模型时，光标旁显示「文本识别中…」（或等价键），成功后换译文；失败/超时用既有错误类文案。语言包对照与词典命中仍立即显示，不出现识别中。

**Why this priority**: 与视觉路径耗时差大，必须分开预期。

**Independent Test**: 词典未收录词 + Ollama 文本模可用 → 见文本识别中再出释义；有语言包对照 → 无「识别中」。

**Acceptance Scenarios**:

1. **Given** 取词未命中词典且扩展翻译开，**When** 等待文本模型，**Then** 显示文本识别进行中，而非图片识别文案。
2. **Given** 对照段无包、等待文本整句模型，**When** 等待中，**Then** 显示文本识别进行中。
3. **Given** 词典命中或语言包对照可用，**When** 悬停，**Then** 立即显示结果，不显示识别中。

---

### User Story 3 - 无法翻译与管道错误可区分 (Priority: P2)

玩家能分辨：空白/不可用、文本失败、图片失败。悬停模式按钮上不刷状态。

**Why this priority**: 降低「卡住了」的误解。

**Independent Test**: 人为停 Ollama 后分别触发文本与（若可）图片路径，文案不同或带管道说明；空白处不持续刷无关提示。

**Acceptance Scenarios**:

1. **Given** 文本管道失败，**When** 悬停，**Then** 错误文案指向文本/翻译失败，不是图片识别中。
2. **Given** 图片管道失败，**When** 悬停，**Then** 错误文案指向图片识别失败。
3. **Given** 鼠标在模式浮窗上，**When** 悬停，**Then** 不显示识别中或无法翻译抢焦点。

---

### Edge Cases

- 视觉兜底不在取词模式下对「无字符串」强行识单词；无字符串时取词模式可提示无法翻译或引导切对照段（plan 选定一种，默认：取词模式无串 → 无法翻译，不自动开视觉）。
- 对照段模式（或 plan 指定的「允许视觉」模式）下无串才走视觉。
- ROI 过小或全透明：失败，不崩溃。
- 世界投影文字仍不采集、不视觉（继承 006）。
- Rival 冲突模组时定格整体不生效。
- `qwen2.5` 文本模不得用于送图；必须用 `qwen2.5vl`。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 当定格悬停处**没有**可用绘制管线主语言字符串，且功能允许视觉兜底、扩展翻译开启时，MUST 将光标附近定格画面区域交给本机 Ollama 视觉模型，得到**一句或短段落**译文（粒度在 plan 中选定并固定）。
- **FR-002**: 视觉兜底 MUST NOT 用于单词级取词。
- **FR-003**: 视觉模型 id MUST 固定为 `qwen2.5vl:3b`（除非同一规格修订）；MUST NOT 向玩家开放任意模型作为常规选项。
- **FR-004**: 模组发布包 MUST NOT 捆绑原生 OCR 引擎或 OS 专用 OCR 运行时。
- **FR-005**: 等待**文本**机翻时，悬停提示 MUST 使用「文本识别中」类文案（语言键），MUST NOT 使用图片识别文案。
- **FR-006**: 等待**视觉**机翻时，悬停提示 MUST 使用「图片识别中」类文案。
- **FR-007**: 无法提供结果时 MUST 可显示「无法翻译」；超时与失败 MUST 有明确文案，并须能区分或标注文本/图片管道。
- **FR-008**: 语言包对照与词典即时命中 MUST NOT 显示识别中状态。
- **FR-009**: 视觉与文本扩展翻译 MUST 受同一或关联的客户端开关约束；关闭后 MUST NOT 发起视觉请求。
- **FR-010**: 视觉请求 MUST 仅本机 endpoint；结果宜缓存；MUST 有超时。
- **FR-011**: 取词模式下无绘制字符串时 MUST NOT 自动走视觉识词（见 Edge Cases）。

### Key Entities

- **LookupPipeline**: TEXT_DICT | TEXT_MT | VISION_MT | NONE
- **HoverStatus**: IDLE | TEXT_PENDING | VISION_PENDING | OK | FAILED | TIMEOUT | UNAVAILABLE
- **VisionRequest**: ROI 图像引用 + 模式 + 缓存键

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 无绘制字符串且视觉可用时，悬停后先出现图片识别中，再在超时前出现句/段译文或错误。
- **SC-002**: 文本机翻等待中只出现文本识别中，不出现图片识别中。
- **SC-003**: 关闭扩展翻译后，无字符串区域不再触发视觉模型网络/本机请求。
- **SC-004**: 发布 jar 中不含独立 OCR 原生库；视觉依赖仅文档要求玩家安装 Ollama VL 模型。
- **SC-005**: 词典/语言包即时结果不出现「识别中」闪烁。

## Assumptions

- 建立在 007 定格扩展（配置、文本 Ollama、模式切换）之上。
- 定格帧缓冲已存在，可裁 ROI。
- 短段落与单句的取舍以实现简单为准，默认倾向「光标附近一块 ROI 内的连续文字（一句或短段）」一次视觉调用。
- 主语言仍限 `en_us` / `zh_cn`。扩展翻译（文本机翻与视觉兜底）**暂定英→中**：prompt 固定产出简体中文，与 007 文本 Ollama 一致；不随主语言切换译出方向（日后若扩展再开规格）。
- 世界投影文字不采集/不视觉、Rival 冲突时整组定格停用：继承 006/007，本 feature 不单独立项回归。
