# Research: 中英主语言快捷切换

## 切换什么

- **Decision**: 快捷键更换的是整套跟随游戏语言的界面文字，不是只调换提示框里哪一行当标题。001 的第二行规则不变：额外行是语言对里当前标题没用的那一种。
- **Rationale**: 用户把该快捷键和原版语言切换对比，并要求启动时两套文案都在。只改提示框标题则不需要更换游戏语言。这个范围写在规格 Assumptions 里。
- **Alternatives considered**: 菜单留在原语言，只交换提示框主次行。范围小很多，但和「切换显示的主语言」不符。若要改回这个窄范围，先改规格再改本计划。

## 如何避免完整重载

- **Decision**: 不调用客户端的完整资源重载。001 在普通资源加载里已经建好两份 `ClientLanguage`。按键时把目标那一份安装为当前语言，并把原版选项的语言代码改成 `zh_cn` 或 `en_us` 后保存。
- **Rationale**: 完整重载会重读材质、模型和音效，出现进度画面。语言管理器单独重读 JSON 也比直接换上缓存慢，而且第一次按键之前第二语言行已经证明文本在内存里。
- **Alternatives considered**: 调用 Language Reload 同款的「只重载语言管理器」。那仍会重新解析语言文件，而且那份实现是 Fabric。可以作为装不上缓存时的后备：只用当前已经打开的资源管理器重读语言，仍然不走完整资源重载。实现时先对照 21.1.251 的 `LanguageManager` 字段，确认缓存安装的访问点，再决定是否需要后备。

## 按键

- **Decision**: 注册一个本模组分类下的按键，默认不绑定单键。未设置单键时，世界中、背包中和暂停菜单里，F3 按住且 J 刚按下即切换。玩家在控制设置里绑定单键后，改为该单键，F3+J 不再切换。聊天输入界面打开时两种方式都不触发。
- **Rationale**: 原版和 NeoForge 的按键修饰只有 Shift、Control、Alt，表达不了 F3+J。用户又要求能改键。把「默认和弦」和「玩家改成的单键」分成两个状态，控制设置里能看见这个动作。
- **Alternatives considered**: 只做不可改的 F3+J。违反「可以在控制设置中更改」。把 J 本身设成默认单键，会偏离用户指定的默认组合，也容易在界面里误触。

## 刷新哪些界面

- **Decision**: 换上语言后按这个顺序刷新：窗口标题、聊天缓存、当前屏幕的控件重建、打开的书页缓存、打开的进度界面、已加载区块中告示牌正反面的排版缓存、文本展示实体的行缓存。
- **Rationale**: 这些是 Language Reload 1.21.1 在语言管理器重载后补刷的原版缓存，再加上规格点名的「已经打开的背包和暂停菜单」。背包和暂停菜单的文字是打开时生成的，所以要重建当前屏幕的控件。
- **Alternatives considered**: 只换语言对象，不重建屏幕。已经打开的暂停菜单会保持旧文字，通不过 SC-002。对所有已加载模组界面逐个打补丁，超出本阶段。

## 语言对之外的启动语言

- **Decision**: `LanguageCycle` 是纯函数。当前代码不是 `zh_cn` 或 `en_us` 时，下一次目标是 `zh_cn`。是 `zh_cn` 时下一次是 `en_us`。是 `en_us` 时下一次是 `zh_cn`。按键前不调用它。
- **Rationale**: 对应 FR-010 和 FR-011，并且可以不启动游戏就测完。
- **Alternatives considered**: 第一次按键切到英文。规格指定第一次进入简体中文。记住原来的第三种语言并在循环里带回它，违反「只在中英之间交替」。

## 缺包

- **Decision**: 构建某一语言失败或该语言表为空时，仍然允许按键把选项切过去，但 001 的省略规则继续生效，不合成翻译键行。两种都失败时按键不改变语言。
- **Rationale**: 缺包要能进世界。切到一份空语言仍会让界面掉回翻译键，所以两种都不可用时不切。只有一种可用时允许切到可用的那种；切到空表时界面会显示原版缺词行为，quickstart 要记下实际结果。若空表会把大量键显示出来，实现时改为拒绝切到空表，并在计划的契约里保持「不把翻译键当成第二语言行」。
- **Alternatives considered**: 缺包时禁用整个模组。违反 FR-014。
