# Minecraft 中英双语显示模组 - 需求与实现方案

## 1. 项目概述

### 背景
现有中英双语相关模组（如与 Jade、JEI、AE2 集成的物品信息双语显示模组）大多仅聚焦于物品提示框和搜索，无法覆盖菜单项、地图名称、对话内容等更广泛的 UI 与文本场景。完整双语显示面临文本过长、长句翻译、性能与兼容性等硬性限制。

### 目标
开发一个**客户端模组**，实现更完整的中英双语显示能力，同时支持：
- 物品、流体、菜单、部分 GUI 文本的双语展示
- 全局快捷键快速切换显示模式（主语言 / 副语言 / 双语）
- 虚拟「拼音」语言，实现无需切换中文输入法的混合搜索
- 模块化设计：显示逻辑与翻译数据源分离

### 核心原则
- **显示与数据分离**：本模组只负责双语显示与切换逻辑，翻译文案优先来自现有 i18n 资源包（如 I18nUpdateMod3 + Minecraft-Mod-Language-Package）。
- **非强制依赖**：不强依赖 PolyglotTooltip 或 Language Reload，而是参考其实现思路，自行实现核心功能。
- **客户端优先**：仅客户端运行，不要求服务端安装。
- **可配置**：显示策略、字号、布局、是否启用拼音等均可通过配置调整。

## 2. 核心功能需求

### 2.1 双语显示
- 支持物品名称、提示框、部分菜单标题、常见 GUI 文本的中英双语显示。
- 对单行文本（如物品名）：中文与英文可拼接在同一行。
- 对多行文本：中文内容置于英文下方（或可配置顺序）。
- 第二语言字体字号可单独缩小，以缓解文本过长导致显示不全的问题。
- 在高分辨率（2K+）或 Mac 视网膜屏幕下，通过整体缩小字体 + 布局策略改善显示效果。

### 2.2 全局快捷键切换
- 提供全局快捷键，在以下模式间快速切换：
  - 仅显示主语言
  - 仅显示副语言
  - 双语同时显示
- 切换仅修改内存中的显示模式，**不触发资源包完整重载**，实现近乎即时的响应。
- 可参考 Language Reload 的多语言加载与快速切换思路。

### 2.3 拼音虚拟语言搜索
- 创建一个虚拟的「pinyin」语言（或直接注入拼音搜索文本）。
- 将中文物品名称转换为全拼或首字母拼音，加入可搜索文本。
- 利用现有多语言搜索机制（参考 PolyglotTooltip），使玩家在英文输入法下即可通过拼音搜索物品。
- 解决中文输入法下无法使用 WSAD 移动的痛点。
- 拼音仅参与搜索，默认不在提示框中显示。

### 2.4 翻译数据来源
- 优先读取已加载的资源包中的语言文件（en_us、zh_cn 等）。
- 强烈推荐配合 I18nUpdateMod3（自动汉化更新模组）+ Minecraft-Mod-Language-Package 使用，以获得较完整的中文翻译覆盖。
- 本模组本身在无外部翻译包时仍可运行，但副语言覆盖率会下降。

## 4. 技术实现要点

### 4.1 语言加载与缓存
- 同时持有主语言与副语言的 Language 映射。
- 建立物品/文本键到双语名称的缓存，避免每次渲染时重复查询。
- 拼音映射同样需要缓存（可异步生成并持久化到本地文件）。

### 4.2 显示策略
- 可配置项：
  - 双语顺序（中文在上/英文在上）
  - 单行拼接 vs 多行堆叠
  - 主语言与副语言的字号比例
  - 分隔符样式（空格、括号、换行等）
  - 是否在提示框中显示副语言
- 在高分辨率下优先通过缩小整体字体 + 副语言更小字号来解决溢出问题。

### 4.3 拼音生成
- 推荐使用 `pinyin4j` 或类似轻量库进行中文转拼音。
- 支持全拼与首字母两种模式（可配置）。
- 处理多音字时采用简单策略（如取第一个读音）。
- 生成结果注入到搜索索引，而非修改原始语言文件。

### 4.4 兼容性范围（优先级）
1. 物品提示框（核心）
2. JEI / EMI 搜索与显示
3. AE2 终端搜索
4. Jade / Waila 类覆盖层
5. 常见原版与模组 GUI 标题
6. 其他自定义渲染界面（后续扩展）

硬编码文本和完全自定义渲染的模组需要单独兼容处理。

## 5. 开发与测试流程

### 5.1 推荐开发环境
- 使用 NeoForge MDK + IntelliJ IDEA。
- 日常开发通过 Gradle `runClient`（Debug 模式）启动，**无需每次手动打包 jar**。
- 在 `build.gradle` 中通过 `modRuntimeOnly` 声明 JEI、AE2 等测试依赖，或将 jar 放入 `run/mods` 目录。

### 5.2 热重载策略（仅开发阶段）
- 方法体修改：IDE 普通 HotSwap 即可。
- 更复杂改动：可配置 DCEVM + Hotswap Agent。
- 语言文件、显示配置、拼音映射等数据驱动部分：通过 F3+T 或资源重载模组快速验证。
- 大改动或 Mixin 相关修改仍可能需要重启，但应使用精简测试环境而非完整 ATM10。

### 5.3 测试分层
- **日常开发**：IDE `runClient` + 必要模组（JEI、AE2、Jade 等）。
- **最终验证**：打包正式 jar，放入 HMCL 启动的完整整合包（如 ATM10）中测试兼容性。

## 6. 约束与注意事项

- 文本过长问题无法完全消除，只能通过字号缩小、布局优化和可选的悬停显示等方式缓解。
- 完整覆盖所有菜单、对话、地图名称等场景难度较高，建议分阶段实现（先物品与常见 GUI，再逐步扩展）。
- 性能方面需重视缓存，避免在渲染路径中进行重复计算或拼音转换。
- 模组应尽量减少对特定版本 API 的硬依赖，以提升长期维护性。
- 正式发布版本不需要热重载能力。

## 7. 建议的配置选项（示例）

```yaml
# 示例配置结构（非最终格式）
display:
  mode: bilingual          # primary / secondary / bilingual
  primary_language: zh_cn
  secondary_language: en_us
  layout: stacked          # stacked / concatenated
  secondary_font_scale: 0.8
  show_secondary_in_tooltip: true

search:
  enable_pinyin: true
  pinyin_mode: full        # full / initials
  inject_into_polyglot: true  # 若检测到 PolyglotTooltip 则尝试兼容

hotkey:
  toggle_mode: "key.keyboard.f6"
```
